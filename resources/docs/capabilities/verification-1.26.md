## 1.25 decisions

- **Tool approval / Harness:** [tagged options](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentOptions.cs) and [approval implementation](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI/ChatClient/ApprovalResponseBindingChatClient.cs) reject saved unanswered requests on the next underlying run, including empty input and partial batches. Binding must be enabled. A successful run consumes pending state; failed/early-stopped streams can retain it. Generated decisions precede tool results but do not prove run success or atomic execution/history storage. The [decision record](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/docs/decisions/0045-dotnet-unanswered-tool-approvals.md) still has proposed frontmatter, so implementation/options corroborate it. [Standing approval documentation](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI/Harness/ToolApproval/ToolApprovalRequestContentExtensions.cs) warns that rules survive in session state across changed agent/tool instances. Current [Learn approval guidance](https://learn.microsoft.com/agent-framework/agents/tools/tool-approval) explains the request/new-run protocol but does not supply these version-specific recovery details.
- **Sessions/history:** [Cosmos options](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI.CosmosNoSql/CosmosChatHistoryProviderOptions.cs) and [provider](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI.CosmosNoSql/CosmosChatHistoryProvider.cs) replace trailing constructor parameters with options; preserve client ownership, state key and filters. PartitionKeyFactory controls storage/read/count/delete keys; metadata is independent. A flat key with tenant metadata is possible but not authorization or an automatic data migration.
- **Declarative workflows:** [extractor](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Entities/EntityExtractor.cs) supports EmbeddedEntity/ClosedListEntity, trimmed case-insensitive display/synonym matching before ID matching, returning the item ID. Unknown values follow invalid-question handling. Current [Learn declarative guide](https://learn.microsoft.com/agent-framework/workflows/declarative) remains a schema overview; the tag determines exact support.
- **Orchestrations:** [handoff implementation](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/HandoffAgentExecutor.cs) continues a retained participant session without resubmitting the original user command; reasoning-only remnants of filtered calls are dropped. One builder method comment describes reissuing the latest user input, contradicting that implementation and the class remarks; do not prescribe command replay. [Agent host options](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI.Workflows/AIAgentHostOptions.cs) require completed call/result pairs before forwarding external approval answers, even when ordinary input forwarding is disabled.
- **Observability:** [OpenTelemetryAgent](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI/OpenTelemetryAgent.cs) preserves agent response/update continuation state instead of round-tripping through only provider representations. The [Learn observability guide](https://learn.microsoft.com/agent-framework/agents/observability) documents configuration; tagged code supplies this fix.
- **Hosting/protocols:** [Chat Completions SSE](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI.Hosting.OpenAI/ChatCompletions/AIAgentChatCompletionsProcessor.cs) adds the terminal `data: [DONE]` only on normal completion. [Central dependencies](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/Directory.Packages.props) upgrade A2A/ASP.NET Core SDKs to 1.0.0-preview3; no universal protocol parity follows. [Foundry toolbox](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FoundryToolboxService.cs) scopes deferred/consent-resolution caches to a response with a unique internal identity, not a reusable platform call ID. Startup caches remain distinct. [Purview processing](https://github.com/microsoft/agent-framework/blob/dotnet-1.25.0/dotnet/src/Microsoft.Agents.AI.Purview/ScopedContentProcessor.cs) additionally includes text/reasoning annotations, error details and data names in policy checks.
- **Excluded migrations:** Harness progress instruction change and its revert cancel out. AgentMemory is an unofficial sample dependency upgrade, not a new core MAF persistence contract.

## 1.26 decisions

- **Sessions/context:** [AgentSessionStore](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStore.cs) adds abstract DeleteSessionAsync(agent, key, cancellationToken); absent sessions are a no-op. Custom stores/decorators need the matching implementation and isolation. Local session deletion does not promise deletion of remote history, files, checkpoints or domain data. FoundryMemory/Mem0 now preserve caller cancellation rather than logging it as ordinary memory failure.
- **Tools/middleware:** [ToolApprovalAgent](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI/Harness/ToolApproval/ToolApprovalAgent.cs) rejects duplicate active request IDs. [Declarative function executor](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/ObjectModel/InvokeFunctionToolExecutor.cs) honors registered ApprovalRequiredAIFunction even without YAML requireApproval, snapshotting AutoSend per invocation. [MCP handler](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative.Mcp/DefaultMcpToolHandler.cs) validates invocation header names/values. [Function middleware remarks](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI/FunctionInvocationDelegatingAgentBuilderExtensions.cs) exclude FICC.AdditionalTools; [chat-pipeline context-provider remarks](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI/AIContextProviderDecorators/AIContextProviderChatClientBuilderExtensions.cs) also identify unsupported interception/order combinations. These are limits to enforcement, not equivalent substitutes for tool-local authorization.
- **Workflows:** [StatefulExecutor](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Workflows/StatefulExecutor.cs) reads current context state instead of an instance cache. [Executor callbacks](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Workflows/Executor.cs) restore state before post-load hooks, deduplicating shared callbacks by key instance. [Root executor](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Kit/RootExecutor.cs) resets compiled formula state/generated conversation IDs. [Expression engine](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/PowerFx/WorkflowExpressionEngine.cs) preserves sensitivity, redacts sensitive evaluation errors, and control-flow executors reject sensitive values. Variable metadata is case-sensitive; approved AutoSend is snapshotted across waits/restore. [Visitor](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/WorkflowActionVisitor.cs) warns when skipping unsupported actions: a warning is not strict rejection. [Fan-out runner](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Workflows/Execution/FanOutEdgeRunner.cs) deduplicates target IDs within one dispatch, not business operations across retries.
- **Hosting:** [AG-UI endpoint mappings](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Hosting.AGUI.AspNetCore/AGUIEndpointRouteBuilderExtensions.cs) honor DI lifetimes/request services and add a request selector. Stable registration/agent names partition sessions; null selection returns 404 before state lookup. Selection does not authorize callers. Explicit null SSE fields are preserved. [Foundry consent handling](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/ConsentAwareMcpClientAIFunction.cs) preserves OAuth consent detail and uses oauth_consent_request; malformed consent must fail closed. A2A preserves non-routine status messages, rejects outbound empty transferable content and invalid card configuration; direct gRPC uses A2A.Grpc and caller-owned clients. [Learn A2A](https://learn.microsoft.com/agent-framework/hosting/self-hosting/a2a/dotnet) separates agent-card publication from endpoint mapping.
- **DevUI:** [options](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.DevUI/DevUIOptions.cs) and [validator](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.DevUI/DevUIRequestValidator.cs) require loopback peer/Host and reject cross-site state-changing browser requests by default. UI bearer token and ConfigureEndpoints do not automatically secure separately mapped standard OpenAI routes. Aspire adds local browser/Host checks as well. These controls are for trusted development, not public reverse-proxy authentication.
- **Harness/files/shell:** [file store](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI/Harness/FileStore/AgentFileStore.cs) adds bounded multi-step search and cancellation. [Docker options](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/src/Microsoft.Agents.AI.Tools.Shell/DockerShellExecutorOptions.cs) rename ExtraRunArgs to UnsafeExtraRunArgs, for developer-controlled configuration only; defaults cannot certify container isolation. [Dependency changes](https://github.com/microsoft/agent-framework/blob/dotnet-1.26.0/dotnet/Directory.Packages.props) include A2A.Grpc preview3, MessagePack 3.1.12 and Aspire 13.6.1. Do not copy repository sample dependency pins into adopting applications without review.

## Unchanged boundaries and limits

Adoption, least-agentic architecture, general multimodal/structured-output support, provider background-response restrictions, durable integration lifecycle and runtime skill discovery received no new broad verification. Their 1.24 evidence remains unchanged. [Current Hooks Learn](https://learn.microsoft.com/agent-framework/agents/agent-hooks) still conflicts with .NET alpha source; [FIDES Learn](https://learn.microsoft.com/agent-framework/agents/security) still states Python-only. No new .NET FIDES or stable Hooks support is inferred. Declarative agents and managed-hosting maturity were not globally reverified.

This is documentary/tag review, not installed API validation. No C# build, application/runtime security guarantee, live-provider call, native-client installation or autonomous routing result is asserted. Run the new fixtures in fresh sessions and application-level deterministic tests before relying on these changes in an adopting application.
