# One development process, MAF-specific architectural contribution

Read applicable project instructions and the current conversation/design before introducing process. The process already active owns sequencing, artifacts and approvals. Available Superpowers skills alone do not mean a Superpowers workflow is active.

| Active process | How MAF guidance contributes |
|---|---|
| Superpowers brainstorming/planning/execution | Supply relevant agent-design questions, architectural decisions, patterns and API checks inside that same workflow. Reuse its answers and canonical design; keep its approval requirements. |
| Team RFC/ADR/refinement or another development skill | Follow that process and documentation convention, adding the same MAF-specific judgment. |
| No process | Discover consequential unknowns, discuss alternatives when meaningful, capture a proportional design, and implement when sufficiently specified and authorized. No Superpowers installation is required. |

A complete existing design receives a gap assessment, not a restart. A narrow exact change follows the project's small-change process. An implementation request does not require invoking architecture, adoption or a second planning skill solely to perform that assessment. Do not add a plugin-wide approval ceremony; honor explicit delegation and the active process instead.

Use one context index and canonical document per concern. Reuse settled requirements and preserve their provenance; raise a conflict only when new evidence changes them. For document placement and unknown conventions, use [project context and refinement](project-context-and-refinement.md). Installation supplies developer guidance; adoption is a separate explicit merge of project instructions, not a prerequisite to ordinary assistance.
