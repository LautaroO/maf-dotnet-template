Maintainer inspection of event logs and resulting files confirmed:

- Embedded adoption appended root boundary guidance and created only `src/Orders.AI/AGENTS.md`. AI-first adoption appended guidance to the existing root. Both retained the original root text, existing documentation convention and sentinel. No skill duplicates or build/restore artifacts were created. Context distinguishes declared package versions from unverified installed APIs and marks absent runtime/provider/state details unknown.
- Ordinary .NET probes before and after embedded adoption reported no selected skills; event logs showed no MAF skill reads or file changes.
- Maturity review selected agents, workflows, security, middleware and tools guidance. It correctly distinguished declarative agent RC, stable declarative workflow/Harness packages, experimental composed APIs, published .NET Hooks alpha with the Learn discrepancy, and Python-only reviewed FIDES. It offered deterministic .NET middleware/tool authorization without claiming equivalent FIDES enforcement.
- Checkpoint review selected workflows and testing guidance, required stable logical-role participant identities and compatible topology/names, separated tenant/session IDs, rejected assumptions that new IDs repair old checkpoint lineage, and proposed deterministic fake-model compatibility tests.
- An initial AI-first inspection was deliberately not accepted as a completed adoption because it ran read-only. The separate writable session listed above applied and verified the actual merge.

These are representative instruction/routing smoke checks, not a full behavioral evaluation of every fixture or a runtime certification. Both adoption profiles and positive/negative cases were reviewed in native CLI fresh sessions, satisfying the [release smoke gate](fresh-session-smoke-test.md).
