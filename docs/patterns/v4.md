# MAF .NET pattern catalog v4

Catalog version: 4.0.0. These fragments communicate boundaries, not package-version-locked APIs. Verify installed NuGet packages before coding.

## 1. Existing-application adoption

### Intent
Add MAF without displacing the application's architecture or instructions.
### Responsibility classification
Adoption guidance and repository boundaries; no runtime agent behavior.
### Recommended abstraction
`$maf-adoption`, shared repo Codex skills, root boundary fragment, and a nested AI-module `AGENTS.md`.
### State and trust boundaries
Existing root rules are authoritative; infer no package, command, provider, or ownership facts.
### Maturity/provider constraints
Profile placement is framework-independent; installed MAF packages remain authoritative.
### Illustrative C# fragment
`Domain <- Application <- AI/MAF` (dependency direction, not a namespace prescription).
### Implementation prompt
“Inspect this solution, classify its shape, and propose a non-overwriting hierarchical guidance merge with evidence-backed context.”
### Review checklist
Root preserved; local conventions retained; AI removal leaves domain/use cases intact; context has no guesses.
### Acceptance/evaluation criteria
Generic .NET work follows existing rules and does not trigger unrelated MAF skills.

## 2. Conversational assistant with sessions and streaming

### Intent
Serve multi-turn conversation with incremental output.
### Responsibility classification
Agent for language; `AgentSession` for conversation state; host adapter for transport.
### Recommended abstraction
`AIAgent`/`ChatClientAgent`, explicit session creation/reuse, and `RunStreamingAsync`.
### State and trust boundaries
Bind session IDs to authenticated tenancy; treat stream updates and client disconnects as untrusted/incomplete.
### Maturity/provider constraints
Streaming event shapes and provider-side history differ.
### Illustrative C# fragment
`await foreach (var update in agent.RunStreamingAsync(input, session, cancellationToken: ct)) { /* project safe events */ }`
### Implementation prompt
“Implement a session-scoped streaming assistant with authenticated session lookup, cancellation, limits, and provider-neutral output projection.”
### Review checklist
No static session; cancellation propagates; partial streams do not prematurely commit state; retention is explicit.
### Acceptance/evaluation criteria
Two turns preserve intended context; disconnect/cancel/isolation tests pass without a live model where possible.

## 3. Multimodal agent

### Intent
Accept text plus supported image/audio/file content.
### Responsibility classification
Host validates media; agent interprets it; storage/scanning remain deterministic services.
### Recommended abstraction
MAF/MEAI content types through an `AIAgent`; upload references projected at the provider boundary.
### State and trust boundaries
Validate MIME, size, URI, ownership, malware and retention before model access.
### Maturity/provider constraints
Supported modalities, URI fetches and upload semantics are provider-specific capabilities.
### Illustrative C# fragment
`IReadOnlyList<AIContent> content = [new TextContent(prompt), approvedImageContent];`
### Implementation prompt
“Add bounded image input while isolating provider upload APIs and rejecting unsupported modalities before the agent run.”
### Review checklist
No arbitrary URL fetch; media limits enforced; accessibility/fallback behavior and telemetry redaction defined.
### Acceptance/evaluation criteria
Valid media reaches the agent; spoofed/oversized/cross-tenant media fails closed.

## 4. Structured extraction and classification

### Intent
Convert unstructured input into a typed, validated decision.
### Responsibility classification
Agent performs semantic extraction; deterministic validator owns allowed values and invariants.
### Recommended abstraction
Provider-supported structured output into a dedicated immutable record, followed by validation.
### State and trust boundaries
Model output is untrusted until schema and business validation succeed.
### Maturity/provider constraints
Schema fidelity varies; define unsupported and bounded repair behavior.
### Illustrative C# fragment
`public sealed record Classification(string Label, double Confidence);`
### Implementation prompt
“Return a typed classification, validate label/confidence in C#, and fail closed after a bounded repair attempt.”
### Review checklist
No regex over prose; unknown fields/values tested; no direct side effect from raw output.
### Acceptance/evaluation criteria
Valid, missing, malformed, adversarial and unsupported-provider cases have deterministic outcomes.

## 5. Bounded read-only tools

### Intent
Let an agent retrieve narrowly scoped application data.
### Responsibility classification
Tool adapts an authorized application query; agent decides whether to call it.
### Recommended abstraction
`AIFunctionFactory`/`AITool` over a small application service interface.
### State and trust boundaries
Authenticate/authorize resource access inside the tool; validate arguments and constrain result size.
### Maturity/provider constraints
Requires provider tool calling; tool schema limits vary.
### Illustrative C# fragment
`Task<OrderView> GetOrderAsync(Guid id, CancellationToken ct) => useCase.GetAuthorizedAsync(id, ct);`
### Implementation prompt
“Expose one read-only order lookup tool with caller-scoped authorization, cancellation, timeout, and bounded projection.”
### Review checklist
No generic DB/HTTP client; one capability; tenant checks; untrusted result handled as data, not instructions.
### Acceptance/evaluation criteria
Authorized lookup succeeds; enumeration, injection and cross-tenant tests fail safely.

## 6. Approval-gated side effects

### Intent
Permit consequential actions only after informed approval.
### Responsibility classification
Agent proposes; workflow/tool gate validates and requests approval; application service executes idempotently.
### Recommended abstraction
MAF tool approval or workflow request/response bound to the exact call occurrence.
### State and trust boundaries
Approval includes material arguments and principal; replay cannot authorize a changed call.
### Maturity/provider constraints
Protocol adapters must preserve approval/resume semantics.
### Illustrative C# fragment
`public sealed record ApprovedAction(string CallId, string PrincipalId, string ArgumentsHash);`
### Implementation prompt
“Add occurrence-bound approval for refunds, reauthorize after argument changes, and use an idempotency key.”
### Review checklist
Prompt consent is insufficient; authorization repeats at execution; deny/timeout/replay paths tested.
### Acceptance/evaluation criteria
No side effect occurs without valid approval; duplicates produce one business effect.

## 7. Deterministic/two-step RAG

### Intent
Always retrieve controlled context before generation.
### Responsibility classification
Deterministic retrieval/context provider selects evidence; agent synthesizes.
### Recommended abstraction
AI context provider or explicit retrieval service before `RunAsync`.
### State and trust boundaries
Authorize corpus access; label retrieved text as untrusted evidence; preserve citations/provenance.
### Maturity/provider constraints
Retrieval store is replaceable and independent of model provider.
### Illustrative C# fragment
`var context = await retriever.SearchAsync(query, principal, ct);`
### Implementation prompt
“Implement authorized two-step RAG with deterministic retrieval limits, citations, and a no-evidence response.”
### Review checklist
Retrieval testable alone; prompt injection cannot grant tools; tenant filters precede ranking.
### Acceptance/evaluation criteria
Groundedness, citation accuracy, retrieval recall/precision, latency and empty-result behavior are measured.

## 8. Agentic and hybrid RAG

### Intent
Let the model choose additional retrieval while retaining baseline context.
### Responsibility classification
Context provider injects mandatory evidence; retrieval tool supports agent-selected exploration.
### Recommended abstraction
Context provider plus bounded read-only retrieval `AITool`.
### State and trust boundaries
Both paths enforce identical authorization, provenance, query/result and egress limits.
### Maturity/provider constraints
Requires tool calling; model behavior must be evaluated for search selection and stopping.
### Illustrative C# fragment
`AITool search = AIFunctionFactory.Create(retriever.SearchAuthorizedAsync);`
### Implementation prompt
“Add hybrid RAG with mandatory policy context and at most three agent-selected searches.”
### Review checklist
No duplicated authority; search loops bounded; citations identify which retrieval path supplied evidence.
### Acceptance/evaluation criteria
Compare task success, retrieval calls, groundedness, cost and latency against two-step RAG.

## 9. Explicit sequential and conditional workflow

### Intent
Guarantee ordered semantic and deterministic steps with validated branching.
### Responsibility classification
Workflow owns process; agents own bounded semantic steps; services own rules.
### Recommended abstraction
`WorkflowBuilder`, focused executors, typed messages and conditional/switch edges.
### State and trust boundaries
Validate agent-produced routing DTOs before sending typed workflow messages.
### Maturity/provider constraints
Exact handler/edge APIs evolve; use the installed workflow packages.
### Illustrative C# fragment
`public sealed record ValidationCompleted(bool IsAccepted, string Reason);`
### Implementation prompt
“Build extract → validate → accepted/rejected workflow with typed messages and no free-text routing.”
### Review checklist
Every path terminates; deterministic rules are outside prompts; cancellation/retry ownership clear.
### Acceptance/evaluation criteria
Branch, invalid output, failure and cancellation tests run with fake semantic agents.

## 10. Fan-out/fan-in processing

### Intent
Run independent observable branches and aggregate them safely.
### Responsibility classification
Workflow graph owns concurrency; branch executors work independently; reducer combines typed results.
### Recommended abstraction
MAF fan-out/fan-in edges rather than hidden `Task.WhenAll` inside one executor.
### State and trust boundaries
Correlate branch IDs, bound parallelism, isolate failures and make aggregation deterministic.
### Maturity/provider constraints
Checkpoint/telemetry behavior depends on installed workflow version.
### Illustrative C# fragment
`public sealed record BranchResult(string BranchId, Result Value);`
### Implementation prompt
“Fan out to bounded document analyses, fan in by correlation ID, and define partial-failure policy.”
### Review checklist
No unbounded concurrency; ordering assumptions explicit; retries do not duplicate effects.
### Acceptance/evaluation criteria
All-success, one-failure, timeout, cancellation and resume aggregation tests pass.

## 11. Human-in-the-loop and resumable workflow

### Intent
Pause safely for external input and resume after process interruption.
### Responsibility classification
Workflow request port owns waiting; checkpoint/durable store owns runtime resumption; app DB owns business records.
### Recommended abstraction
MAF request/response plus checkpoints or durable extension according to survival needs.
### State and trust boundaries
Authorize response tokens and bind them to workflow, tenant, step and expected schema.
### Maturity/provider constraints
Checkpointing alone does not guarantee durable scheduling or process survival.
### Illustrative C# fragment
`public sealed record ReviewResponse(string RequestId, bool Approved, string ReviewerId);`
### Implementation prompt
“Pause for review without polling, persist resumable state, and reject stale or cross-tenant responses.”
### Review checklist
Timeout/escalation defined; replay safe; deployment/restart path tested; domain persistence separate.
### Acceptance/evaluation criteria
Resume after restart produces one outcome for approve, deny, timeout and duplicate response.

## 12. Background and durable execution

### Intent
Run long work beyond one request/stream lifetime.
### Responsibility classification
Provider continuation handles background model response; durable runtime handles process survival; domain service handles effects.
### Recommended abstraction
`AgentRunOptions` continuation where supported, or MAF durable extension/workflow for durable orchestration.
### State and trust boundaries
Protect continuation tokens, persist progress atomically, and bound polling/backoff/deadlines.
### Maturity/provider constraints
Background responses are provider-limited; durable packages/runtime constraints must be verified.
### Illustrative C# fragment
`while (response.ContinuationToken is { } token) { /* bounded delay; continue with token */ }`
### Implementation prompt
“Choose provider background response or durable workflow explicitly and implement bounded, cancelable continuation.”
### Review checklist
No infinite polling; crash/redeploy tested; tokens tenant-bound; cost and abandoned work controlled.
### Acceptance/evaluation criteria
Interruption/resume, expiration, cancellation, duplicate continuation and provider-unsupported cases pass.

## 13. Multi-agent orchestration selection

### Intent
Choose sequential, concurrent, handoff, group chat, Magentic, agent-as-tool, or a custom workflow intentionally.
### Responsibility classification
Workflow owns required process; agents own semantic collaboration; deterministic router owns known rules.
### Recommended abstraction
Use the least autonomous built-in orchestration matching control semantics; custom typed graph otherwise.
### State and trust boundaries
Bound turns, participants, tools, tokens, time and cost; validate final outputs.
### Maturity/provider constraints
Orchestration APIs and provider tool/streaming support vary.
### Illustrative C# fragment
`AIFunction specialist = specialistAgent.AsAIFunction(); // only for model-decided delegation`
### Implementation prompt
“Compare orchestration choices against ordering, routing certainty, bounded autonomy and evaluation needs.”
### Review checklist
No multi-agent theater; stop condition exists; deterministic branch is not delegated to an LLM.
### Acceptance/evaluation criteria
Chosen pattern beats a simpler baseline on task success enough to justify cost/latency/risk.

## 14. Runtime Agent Skills, tools, workflows and Harness Agent selection

### Intent
Choose how an application agent gains reusable capability without confusing developer guidance with runtime content.
### Responsibility classification
Runtime Agent Skill supplies progressively loaded instructions/resources/scripts; tool executes bounded capability; workflow controls process; Harness supplies an opinionated runtime.
### Recommended abstraction
Use runtime skills for reusable agent-facing know-how, tools for actions, workflows for guarantees, Harness only when its operating model fits.
### State and trust boundaries
Treat discovered skill files/scripts as supply-chain inputs; allowlist sources and sandbox execution.
### Maturity/provider constraints
Runtime Agent Skills/Harness are evolving .NET capabilities; verify package/version support.
### Illustrative C# fragment
`// Repository .agents/skills guide Codex; application runtime skills are loaded by the MAF agent at runtime.`
### Implementation prompt
“Classify this capability among runtime skill, tool, workflow and Harness; do not package repo Codex guidance into the agent.”
### Review checklist
No naming confusion; provenance and execution limits defined; simpler abstraction considered.
### Acceptance/evaluation criteria
Skill discovery/loading is bounded and tested; actions still pass through authorized tools.

## 15. Hosting and protocol selection

### Intent
Operate and expose an agent for the intended clients.
### Responsibility classification
Host owns runtime operations; protocol adapter owns translation; application owns policy.
### Recommended abstraction
Decide embedded/self-hosted/durable/Foundry hosting separately from native/OpenAI/A2A/AG-UI/MCP protocol.
### State and trust boundaries
Authenticate, tenant-bind external IDs, enforce request/stream limits, and protect session/checkpoint stores.
### Maturity/provider constraints
.NET hosting/protocol packages may be prerelease; Foundry managed hosting introduces platform coupling.
### Illustrative C# fragment
`builder.AddAIAgent("support", (_, _) => agent); // verify installed hosting API`
### Implementation prompt
“Produce a hosting decision record separating operations from protocol and covering auth, streaming, sessions and durability.”
### Review checklist
Protocol is not mistaken for security/durability; health, scaling, rollout and incident ownership explicit.
### Acceptance/evaluation criteria
Auth/isolation, disconnect/resume, load, deployment and storage-failure tests meet SLOs.

## 16. Provider swap and MAF package upgrade

### Intent
Change model provider or MAF version without rewriting domain/workflow contracts.
### Responsibility classification
Composition root/provider adapter owns SDK construction and capability negotiation; upgrade process owns API reconciliation.
### Recommended abstraction
Provider-neutral `IChatClient`/`AIAgent` boundary plus explicit capability descriptor and focused contract tests.
### State and trust boundaries
Do not leak provider DTOs, exceptions, IDs or persistence assumptions upward.
### Maturity/provider constraints
Tools, structured output, hosted tools, background work, streaming and protocol support require explicit detection.
### Illustrative C# fragment
`public sealed record ModelCapabilities(bool Tools, bool StructuredOutput, bool Background, bool HostedTools);`
### Implementation prompt
“Inventory installed packages, diff official release APIs, swap only composition/adapter code, and test unsupported fallbacks.”
### Review checklist
No silent package upgrade; transitive versions checked; persisted state compatibility and rollback planned.
### Acceptance/evaluation criteria
Neutral contract suite passes for old/new providers; unsupported features fail clearly; quality/cost/latency compared.

## 17. Evaluation, observability, incident diagnosis and production review

### Intent
Prove semantic and operational quality and diagnose failures safely.
### Responsibility classification
Deterministic tests prove code; evaluations measure model behavior; OTel traces/metrics/logs expose runtime boundaries; review assesses residual risk.
### Recommended abstraction
MAF/MEAI evaluation and OpenTelemetry with provider-neutral correlation and evidence-first `$maf-review`/`$maf-security` findings.
### State and trust boundaries
Redact content by default; control evaluator data egress; correlate durable/streamed work without exposing secrets.
### Maturity/provider constraints
Token/cost/safety metadata and telemetry conventions vary by provider and package version.
### Illustrative C# fragment
`using Activity? run = source.StartActivity("agent.run"); // record IDs/metrics, not sensitive bodies by default`
### Implementation prompt
“Define offline tests, model evals, SLOs, trace boundaries, privacy controls, incident queries and a production readiness review.”
### Review checklist
Measure task success, groundedness/retrieval, safety, tool correctness, latency, cost, streaming, durability and isolation.
### Acceptance/evaluation criteria
Regression thresholds, alert ownership, redaction tests, trace correlation and incident drill outcomes are documented.
